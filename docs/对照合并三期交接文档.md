## 0. 项目背景（一分钟速览）

- **是什么**：本地 Markdown 编辑器 Chrome 扩展 + Tauri EXE 桌面版（同一份前端代码双端复用）。用 CodeMirror 6（`@codemirror/merge` 6.12）做差异对比与合并。

### 3.1 移动块检测 —— `src/compare/move-detection.js`（新建，纯算法）

- **性能降级**：配对超过 `maxPairs`（200）时 `truncated=true`，渲染层据标志「仅高亮不连线」。

1. **三栏 ≠ 真三文档 MergeView**：库 `@codemirror/merge@6.12.2` 的 `MergeView` 仅支持 a/b 两栏。实际架构 = `MergeView(Yours + Result)` + **独立可编辑 Theirs EditorView** 并排，并补齐 B↔C 第二层 diff 装饰 + 滚动同步 + 连线。中栏 Result 同时是 A↔B 层的 b 与 B↔C 层的 a。

### 4.2 已完成：三栏重构地基 —— `src/compare-merge.js`（核心改造，5+ 处大改）

- **新增模块级 `DIFF_CONFIG = { scanLimit: 500, timeout: 1500 }`**。
- **`refreshDecorations(viewA, viewB, { wordDiff, moveDetect }, sides)`**：改为 `sides` 参数 + 返回 `{ pairs, chunks, truncated }`。`sides` 守卫：`writeA/writeB`（是否向该视图 dispatch 字词差异装饰）+ `aSide/bSide`（写哪侧移动底纹）。**B↔C 层 `writeA:false, aSide:null`**——否则两层全量替换语义互相覆盖中栏。
- **`computeChunks` 自算**：B↔C 两视图分属不同实例，`getChunks(mv.b.state)` 返回的是 MergeView 自身 A↔B chunks，与本层无关——必须 `Chunk.build(aDoc, bDoc, DIFF_CONFIG)` 自算。
